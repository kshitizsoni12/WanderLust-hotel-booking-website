# MongoDB Atlas and Render Deployment Guide

This README explains how to move your MongoDB database to MongoDB Atlas and deploy your Node.js/Express application on Render.

## Part 1: Move MongoDB to Atlas

### 1. What is MongoDB Atlas?

MongoDB Atlas is a cloud-hosted MongoDB service.

- **Local MongoDB:** Your database runs on your own computer.
- **MongoDB Atlas:** Your database runs on cloud servers and can be accessed by your deployed application.

When you deploy your website, the server on Render cannot automatically access the MongoDB database running on your computer. You need a cloud database such as Atlas.

### 2. What is a Cluster?

A **cluster** is the cloud database deployment that provides the resources needed to store and manage your MongoDB data.

### 3. Create an Atlas Deployment

1. Open [MongoDB Atlas](https://www.mongodb.com/atlas) and create an account or sign in.
2. Create a new project if required.
3. Create a database deployment (cluster). Choose the available plan and region suitable for your project.
4. Wait for the deployment to finish creating.

### 4. Create a Database User

1. Open **Database Access** in Atlas.
2. Create a database user with a username and password.
3. Save these credentials securely.

**Important:** This database user is different from your MongoDB Atlas account login.

### 5. Configure Network Access

1. Open **Network Access** in Atlas.
2. Add the IP addresses that are allowed to connect to your database.
3. For a learning project, `0.0.0.0/0` allows connections from any IP address, but it is broad and less secure. Prefer a more restrictive configuration when possible, and use a strong database password with only the required permissions.

### 6. Get the MongoDB Connection URL

1. Open your database deployment and click **Connect**.
2. Choose **Drivers** and select Node.js.
3. Copy the connection string.
4. Replace the username/password placeholders with your database user's credentials.
5. Add your database name, such as `wanderlust`, in the URL.

Example:

```text
mongodb+srv://username:password@cluster0.xxxxx.mongodb.net/wanderlust?retryWrites=true&w=majority
```

If your password contains special characters, URL-encode them before putting the password in the connection string.

### 7. Store the URL in `.env`

In your project's `.env` file, add:

```env
ATLASDB_URL="mongodb+srv://username:password@cluster0.xxxxx.mongodb.net/wanderlust?retryWrites=true&w=majority"
```

Use your actual Atlas connection URL. Do not share or commit this URL because it contains database credentials.

### 8. Connect Your Application to Atlas

Make sure `dotenv` is loaded before you read environment variables and that Mongoose is imported.

```js
require("dotenv").config();

const mongoose = require("mongoose");

const dburl = process.env.ATLASDB_URL;

mongoose
  .connect(dburl)
  .then(() => console.log("Connected to Atlas"))
  .catch((err) => console.log(err));
```

Adapt this snippet to your existing `index.js` rather than adding a second database connection. Connect to the database before starting the server or accepting requests.

### 9. Does Changing the URL Copy Your Local Data?

**No.** Changing the connection URL only tells your application to use Atlas. It does not copy your existing local database data.

To move your existing data, you can use MongoDB Compass to export and import collections, or use MongoDB Database Tools such as `mongodump` and `mongorestore`. Alternatively, you can insert fresh sample data into Atlas.

**Important project warning:** If your initialization script deletes all listings before inserting sample data, do not run it against your production Atlas database unless you intentionally want to delete that data.

## Part 2: Deploy the Application on Render

### 1. Add a Start Script

In `package.json`, make sure you have a start script similar to this:

```json
"scripts": {
  "start": "node index.js"
}
```

Keep any other scripts your project already uses.

### 2. Listen on Render's Port

In `index.js`, use the port provided by Render:

```js
const PORT = process.env.PORT || 3000;

app.listen(PORT, () => {
  console.log(`Server running on port ${PORT}`);
});
```

Adapt this to your existing `app.listen()` code instead of creating a second server listener.

### 3. Add `.gitignore`

Make sure your `.gitignore` contains:

```gitignore
node_modules/
.env
```

This prevents dependencies and your local secrets file from being committed to Git.

### 4. Push Your Project to GitHub

1. Create a GitHub repository if you do not already have one.
2. Commit and push your project files.
3. Confirm that `.env` and `node_modules` are not uploaded.
4. Keep your source code and `package.json` in the repository.

### 5. Create a Render Web Service

1. Open [Render](https://render.com/) and sign in.
2. Choose **New → Web Service**.
3. Connect your GitHub account and select your repository.
4. Configure the service:

   - **Runtime:** Node
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
   - **Branch:** Select the branch containing your project, commonly `main`

5. Create the web service and wait for the deployment to finish.

### 6. Add Environment Variables in Render

Open your Render service's **Environment** settings and add the variables your application needs.

For example:

| Key | Value |
|---|---|
| `ATLASDB_URL` | Your complete MongoDB Atlas connection URL |
| `CLOUDINARY_CLOUD_NAME` | Your Cloudinary cloud name, if used |
| `CLOUDINARY_KEY` | Your Cloudinary API key, if used |
| `CLOUDINARY_SECRET` | Your Cloudinary API secret, if used |
| `SECRET` | Your session secret, if used |

Only add variables that your application actually uses. Render does **not** automatically receive variables from your computer's `.env` file.

Never put passwords, API secrets, or session secrets directly in public source code.

### 7. Check Atlas Network Access

Make sure Atlas allows connections from your deployed application. If the app cannot connect, check the Atlas Network Access settings, database username/password, connection URL, and Render logs.

Avoid leaving broad network access enabled unnecessarily.

### 8. Test Your Deployed Website

1. Open the URL provided by Render.
2. Test the main pages and features.
3. Check Render's logs if the app fails to start or the database connection fails.
4. Confirm that data is being saved in Atlas.

Some free Render services may spin down after a period of inactivity, so the first request after inactivity can take longer.
